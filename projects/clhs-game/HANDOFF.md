## 和導覽的關係

遊戲從「中壢神社 古今對照」（`../zhongli-shrine/`，Work 004）分岔出來。**不要改動導覽資料夾**，那邊的網址印在海報 QR code 上。

- 直接 import 導覽的 `shrine-proc.js`（神社模型、座標常數）。`?v=` 要和導覽 `main.js` 裡寫的一樣，兩頁才會共用快取。
- 銅馬、狛犬掃描檔與老照片用路徑引用導覽資料夾的檔案，沒有複製。
- `assets/` 的兩張 png 是複製來的：`shrine-proc.js` 用「相對於網頁」的路徑 `./assets/…` 讀它們，所以遊戲頁底下也要有一份。
- 黑松、輪廓線、掃描檔載入的程式抄自導覽 `main.js`（那裡沒有匯出）。兩邊各改各的。
- 導覽的 `main.js`、夜間模式、心願燈籠、六站導覽、航照底圖都沒有帶過來。地面是一塊草地色平面。

## 檔案

```
clhs-game/
  index.html   Work 007 說明頁＋遊戲（單頁，比照望遠鏡的「展開」）
  game.js      場景、第一人稱移動、標記、收集、圖鑑、主迴圈
  items.js     十件寶物：位置、線索、卡片文字、老照片與出處
  img/line.svg 作品集封面線稿
  assets/      shrine-proc.js 需要的兩張字跡貼圖（複製）
```

改 `game.js`、`items.js` 後，把 `index.html` 的 `game.js?v=` 和 `game.js` 裡的 `items.js?v=` 遞增，手機才不會讀到快取。

## 已定案的設計（2026-11-16 與作者討論）

- 單頁、展開式：收合時畫面只自動環視、不接觸控（手指照常捲頁）；按「展開」或「開始尋寶」才全螢幕並接手操作。瀏覽器的返回鍵會縮回。
- 第一人稱。手機：左下半邊按住拖曳是搖桿，其餘地方滑動轉頭，右下「跑」是開關。電腦：WASD／方向鍵、拖曳滑鼠、Shift、E。
- **不擋牆**，建物可以穿過去。地面高度用 `groundAt()` 依各層平台與拜殿、幣殿、本殿地板算，平滑追上。
- 寶物 10 個，順序是走進神社的順序。標記是金色菱形加光柱。石燈籠六座算 1 個，走到任何一座旁都能收集（`also`）。
- 靠近 5.5 公尺內出現「收集」鈕；彼此很近的（神門、狛犬、神馬）取最近的一個。
- 進度存 `localStorage`（鍵 `clhs-game.ch1`），不收集任何資料，沒有 Apps Script。
- 全部找到後出現兩個按鈕，連到 `../zhongli-shrine/#participate-omamori` 和 `#participate-ema`，不自動跳轉。旁邊要保留「當代教育活動的參與創作，非宗教物件」這句。
- 卡片文字取自導覽的六站與地點卡片。改史料時兩邊要一致。介面上統一寫「神馬」。

## 測試

在 repo 根目錄 `python3 -m http.server 8765`，用 Playwright 開手機尺寸（390×844），three.js 的 jsdelivr 網址導到本機 `node_modules`。
`window.__game` 可以直接改 `player.x / z / yaw` 把人移到任何地方，`markers` 有十個標記的位置。
